## 1. 배경과 목표

발주자는 배터리 소재사의 시장조사 담당자다. 밸류체인 전반(고객 셀사·OEM, 소재 경쟁사, 전구체·리사이클링)의 key player 관련 정보가 매일 다량 쏟아지지만, 수집·분류·시계열화가 전부 수작업이다.

**목표**: 공개 정보의 수집·분류·정제·축적을 완전 자동화하고, 그 위에 (1) 회사별 시계열 조회·비교, (2) 정기 보고서 자동 생성, (3) 데이터 기반 인터랙티브 챗, (4) 회사 간 관계도를 얹는다.

**성격**: 사내 공식 서비스. 단, **외부에 공개된 정보만 사용**하므로 보안검토·사내망 배포는 불요. 사외 클라우드(Vercel/Supabase) 무료 티어로 운영한다.

## 2. 사용자

| 구분 | 설명 |
|---|---|
| 일반 사용자 | 사내 시장조사·기획·영업 인력, **20명 이하**. 대시보드 열람, 보고서 열람, 챗 사용 |
| 관리자 | 발주자 1인. 회사 목록 관리, 판매량/캐파 파일 업로드, 관계 승인, 보고서 재생성 |

**인증 (두 가지 병행)**:
1. **회사 이메일 OTP 가입**: 허용 도메인(회사 도메인)의 이메일로 인증번호를 보내 가입. Supabase Auth의 email OTP 사용.
2. **마스터키 접속**: 관리자가 발급·배포한 키 문자열을 입력하면 로그인 없이 게스트 세션으로 접속.

## 4. 데이터 소스 명세

사전 조사(2026-08-28)로 검증된 사실 기반. 판정: ✅ 가능 / ⚠️ 조건부.

| 소스 | 용도 | 판정 | 제약·설계 반영 사항 |
|---|---|---|---|
| 네이버 뉴스 검색 API | 한국어 뉴스 발견 (매일) | ⚠️ | 일 25,000회. **본문 전문 미제공** — title/description(스니펫)/originallink만 반환. 본문은 링크에서 별도로 가져온다(아래 본문 페처) |
| Google News RSS | 한/영/중 뉴스 발견 (매일) | ⚠️ | 비공식·무보증 엔드포인트. **피드당 ~100건, 페이지네이션 없음** → 회사×언어 단위로 피드 분할. 제목+링크만 제공, 본문은 링크에서 별도 취득. 형식: `news.google.com/rss/search?q=<검색어>&hl=<ko|en-US|zh-CN>&gl=<KR|US|CN>&ceid=<KR:ko|US:en|CN:zh-Hans>` |
| 본문 페처 (기사 링크 크롤링) | F2 2차 정독용 본문 취득 | ⚠️ | 네이버·구글이 준 링크의 언론사 페이지에서 본문 텍스트를 **일시적으로** 가져와 LLM에 넣고 폐기(§6.2). robots.txt 존중 + 소스별 정책, 실패·차단 시 스니펫만으로 폴백. DART·EDGAR·CnEVPost는 이미 본문/전문을 주므로 페처 불필요 |
| DART OpenAPI | 한국 공시 + 분기 재무 | ✅ | 무료, 일 20,000건. 법정 공시서류만. **IR PT·컨콜 자료는 미제공** — 언론 보도로 간접 수취, KRX KIND는 2단계 검토 |
| SEC EDGAR API | 미국 공시(8-K/10-K/10-Q) + XBRL 재무 | ✅ | 무료, 10 req/s, User-Agent 헤더 필수. full-text search 있음 |
| yfinance | 주가·시총 (KR `.KS/.KQ`, 중국 `.SZ/.SS`, 홍콩 `.HK`, 일본 `.T`, 미국·유럽) | ⚠️ | 비공식 라이브러리, 429 차단 리스크 → **일 1회 배치 + 캐싱 + 지수 백오프 + 실패 시 전일값 유지** 필수 |
| CnEVPost | 중국 배터리 뉴스 (영문) | ⚠️ | RSS/사이트 수집. 중국 로컬 정보의 1단계 보완 소스 |
| 관리자 파일 업로드 | 판매량·출하량·캐파 | ✅ | 비정기. xlsx/csv 업로드 → 정해진 스키마로 파싱·검증 후 반입 |

**백필**: 런칭 시 주가·분기 재무·공시 이벤트는 **과거 3년** 소급 수집. 개별 기사·공시 원문 자체는 여전히 런칭일부터만 축적한다 — Google News RSS는 최근 ~100건만 반환하고 과거 날짜 조회 기능이 없어 원문 소급이 사실상 불가능하기 때문 (과거 사건은 챗의 명시적 웹검색으로 보완).

**트렌드 시드(신규)**: 단, F5 산업 트렌드 대시보드용 **테마·키워드 집계**는 런칭 시 최근 18개월치를 소급해서 채운다 — 네이버 API의 과거 검색(부분 소급 가능, 품질 낮음, 보조용)과 리서치 에이전트의 웹 조사를 결합한 1회성 추정 작업이며, 매일 파이프라인이 쌓는 실측 집계와 `data_origin`(seeded/measured)으로 구분 표시한다. 개별 기사 원문을 소급 저장하는 것은 아니다(§6.2 저작권 방침 유지).

## 5. 기능 요구사항

### F1. 일일 수집 파이프라인 (Phase 1)

- GitHub Actions 스케줄로 **매일 1회(06:00 KST)** 실행. 수동 재실행 가능(workflow_dispatch).
- `companies.yaml`의 회사별 키워드로 네이버 API·Google News RSS(3개 언어)·CnEVPost를 조회하고, DART·EDGAR 신규 공시, yfinance 주가를 수집해 Supabase에 저장.
- 실패한 소스가 있어도 나머지는 진행하고, 실패 내역을 실행 로그 테이블에 기록.

### F2. 분류·정제 (Phase 1) — 2단계 깊이 파이프라인

뉴스는 제목+스니펫만으로는 얕은 판정밖에 못 하므로, **싼 게이트로 후보를 걸러낸 뒤 통과분만 본문을 정독**하는 2단계로 처리한다.

- **1차 게이트 (전건, 저비용)**: 제목+스니펫만으로 **관련성 필터**(추적 회사·시장과 무관하면 폐기) + **대략적 회사 매핑**. 하루치 원시 수집을 여기서 대폭 줄인다. DART·EDGAR·CnEVPost 항목은 이미 본문을 확보했으므로 게이트를 건너뛰고 곧장 2차로 간다.
- **2차 정독 (게이트 통과분만, 고비용)**: 기사 링크에서 **본문을 일시적으로 가져와**(본문 페처, §6.2) LLM에 넣고 — **① 회사 매핑 확정**(다대다) → **② 카테고리 태깅**(부록 B 8분류+기타) → **③ 거시 테마 매핑·키워드 추출**(F5) → **④ 한국어 요약 생성**(영/중은 번역 겸 요약) → **⑤ 이벤트성 판정** → **⑥ 관계 후보 추출**(F9). 처리 후 본문 텍스트는 폐기하고 요약+링크만 저장한다.
- **본문 취득 실패 폴백**: 페월·차단·robots 금지로 본문을 못 가져오면 스니펫만으로 축약 처리하고, 해당 항목에 `body_fetched=false`를 표시(요약 품질이 낮음을 화면·프롬프트에서 구분).
- **중복 제거**: 같은 사건의 재보도는 클러스터로 묶어 대표 1건만 타임라인에 노출(나머지는 접힘). 본문 페처는 클러스터당 대표 1건에만 적용해 중복 크롤링·비용을 막는다.
- 회사에 매핑되지 않는 정책·시장 뉴스는 **시장/정책 트랙**으로 분류 (부록 B).

### F3. 회사별 시계열 (Phase 1 축적, Phase 2 화면)

두 종류를 축적한다:

- **수치 시계열**: 주가·시가총액(일), 분기 재무 5종 — 매출·영업이익·영업이익률·CAPEX·재고자산 (DART/EDGAR 자동), 판매량·출하량·캐파(관리자 업로드, 비정기).
- **이벤트 타임라인**: F2에서 이벤트로 판정된 기사·공시 (날짜, 카테고리, 요약, 출처 링크).

### F4. 데일리 리포트 (Phase 1)

파이프라인 완료 후 **하루 1개의 완성된 한국어 리포트**를 자동 생성한다(그날 정독한 기사를 근거로).

- **구조 = 밸류체인 세그먼트별 섹션** (§3.1 기준: 자사 / 고객-셀 / 고객-OEM / 경쟁-양극재 / 경쟁-음극재 / 원료-전구체 / 원료-리사이클링). 각 섹션은 아래 둘로 구성:
  - **동향 요약**: 그날 그 세그먼트에서 벌어진 일을 LLM이 몇 문단으로 요약(회사 나열이 아니라 흐름 중심).
  - **주요 기사 Top 5**: 그 세그먼트 관련 기사 중 상위 5건을 제목 · 한 줄 요약 · 출처 링크로 표시. 사용자가 클릭하면 **원문으로 이동**(본문 미저장, 링크 아웃 — §6.2).
- 상단에 F5 산업 트렌드 대시보드(거시 테마·키워드)를 얹어 전체 그림을 먼저 보여준다.
- **중요도 순위**: LLM 판정(이벤트성·밸류체인 영향도)과 중복 클러스터 크기(재보도가 많을수록 화제성 높음)를 합산해 스코어링, 세그먼트별 Top 5를 뽑는다.
- **대시보드 첫 화면 게시 + 구독자 이메일 발송**(Resend, 사용자별 on/off). 이메일에도 요약과 링크만 담고 원문 본문은 넣지 않는다.

### F5. 산업 트렌드 대시보드 (Phase 1)

업계 전체 흐름을 회사 단위가 아니라 **테마**·**키워드** 단위로 요약해, 데일리 브리프 화면 상단에 경량 대시보드로 보여준다.

- **거시 테마**: 지속형 테마 10~20개(예: "수요 전환(EV→ESS)", "가격·원가 압력", "정책·지정학", "기술 전환", "공급망 재편"). F2 처리 중 관련 기사·공시를 테마에 매핑(다대다, 0개 이상). LLM이 신규 테마 후보를 제안하면 **관리자 승인 대기열**을 거쳐 정식 목록에 추가(F9 관계 승인과 동일한 거버넌스 패턴).
- **키워드**: 고정 목록 없이 자유 추출한 개체명·용어의 기간별 언급 빈도. 승인 없이 자동 집계.
- **화면**: 테마별 주간 언급량 추이(최근 18개월), 오늘 · 1개월 전 · 3개월 전 · 6개월 전 · 1년 전 시점의 상위 테마 비교, 두 시점을 비교한 LLM 한 줄 요약(예: "EV 캐즘 신호 확대, 수요가 ESS로 이동 중"), 이번 주 상승 키워드 Top 10.
- **시드와 실측 구분**: 런칭 시 채운 과거 구간은 `data_origin=seeded`(추정치)로, 이후 파이프라인이 매일 쌓는 구간은 `measured`(실측)로 화면에서 구분 표시한다(§4 트렌드 시드 참조).

### F6. 대시보드 (Phase 2)

- **회사 페이지**: 프로필, 수치 시계열 차트(기간 선택), 이벤트 타임라인(카테고리 필터), 주가 차트 위 이벤트 마커 오버레이. **회사 선택 UI는 밸류체인 세그먼트별로 그룹화**(§3.1)해, 원하는 세그먼트를 펼쳐 그 안에서 회사를 고른다.
- **비교 화면**: 회사 2~5개 선택 → 수치 시계열을 같은 차트에 겹쳐 표시 + 이벤트 타임라인 나란히 표시. 지표 선택 가능(주가는 기간 수익률 % 정규화 옵션).
  - **밸류체인 교차 비교 허용**: 세그먼트를 건너 비교할 수 있다(예: OEM × 소재사). 단 세그먼트마다 존재하는 지표가 다르므로(예: OEM엔 판매량·캐파 개념이 없음), **공통 축(주가 정규화 수익률, 이벤트 타임라인)을 기본 비교 축**으로 삼고, 일부 회사에만 있는 지표(판매량·출하량·캐파 등)는 해당 회사에만 그린다.
- **시장/정책 트랙 페이지**: 회사 무관 뉴스의 타임라인.
- 접근 제어: 로그인(OTP) 또는 마스터키 세션 필수.

### F7. 정기 보고서 (Phase 3)

| 종류 | 생성 방식 | 형식 |
|---|---|---|
| 위클리 | 매주 월요일 자동 + 재생성 버튼 | HTML → PDF |
| 먼슬리 | 매월 1일 자동 + 재생성 버튼 | HTML → PDF |
| 반기 | 온디맨드(관리자 버튼) | 마크다운 초안 + 차트 이미지 (사람이 다듬는 용도) |

- 내용: 기간 내 주요 이벤트 하이라이트(카테고리·밸류체인별), 수치 변동 요약(주가 등락, 신규 재무), 시장/정책 동향. 모든 인용은 요약+출처 링크.
- 생성물은 보고서 보관함에 누적, 대시보드에서 열람·다운로드.

### F8. 인터랙티브 챗 (Phase 4)

- **기본: DB 근거 한정.** LLM이 tool-use로 DB를 조회(회사·기간·카테고리 필터, 시계열 조회, 비교)해 답하고, 근거로 사용한 기사·공시 링크를 반드시 표시.
- **웹검색은 사용자가 명시적으로 요청한 경우만** 수행(예: "웹에서 찾아줘" 또는 검색 토글). DB 축적 이전의 과거 정보를 보완하는 용도. 웹검색 결과는 DB 근거와 **시각적으로 구분 표시**.
- DB에 근거가 없으면 없다고 답한다(추측 금지).

### F9. 관계도 (Phase 4)

- 관계 종류: 공급계약, JV/합작, 지분투자, M&A, 고객관계, 기술제휴.
- **생성**: F2 처리 중 LLM이 기사·공시에서 관계 후보를 추출(회사쌍, 종류, 근거 링크, 날짜) → **관리자 승인 대기열** → 승인된 것만 관계도에 반영.
- **화면**: 회사 선택 시 그 회사를 중심으로 한 관계 그래프. 엣지 클릭 시 근거 목록.

### F10. 관리자 기능 (Phase 1부터 점진)

- 회사 목록 관리(`companies.yaml` 편집 반영), 판매량·캐파 파일 업로드(스키마 검증·오류 리포트), 마스터키 발급·폐기, **테마 후보 승인 대기열(Phase 1)**, 관계 승인 대기열(Phase 4), 보고서 재생성, 파이프라인 실행 로그 조회.

## 6. 비기능 요구사항

### 6.1 비용

- Vercel Free + Supabase Free + GitHub Actions(무료 한도) + Resend Free(월 3,000통, 사용자 ≤20명이면 충분)로 시작. 무료 한도 초과가 예상되면 관리자에게 알리는 것으로 족하며, 자동 과금 전환은 하지 않는다.
- LLM: 월 2~5만원 목표. 대량 처리(분류·요약·번역)는 저가 모델, 보고서·챗은 상위 모델.

### 6.2 저작권 (불변 규칙)

- **일시적 정독은 허용, 본문 저장은 금지.** 분류·요약을 위해 기사 본문을 메모리로 가져와 LLM에 넣는 것은 허용하되, 처리 후 원문 본문 텍스트는 **DB·로그·파일 어디에도 남기지 않는다**. 저장 대상은 제목, 출처 링크(originallink), 발행일, 언론사명, **자체 생성 LLM 요약**뿐이다.
- 브리프·보고서·챗 답변의 인용도 자체 요약 + 출처 링크로만 한다.
- 본문 페처는 **robots.txt를 존중**하고, 소스별 수집 정책(허용/차단)을 두며, 차단된 곳은 크롤링하지 않고 스니펫 폴백으로 간다.

### 6.3 LLM 프로바이더 중립 (불변 규칙)

- 모든 LLM 호출은 단일 추상화 레이어를 거친다. 환경변수로 프로바이더 전환: 기본 **Anthropic Claude**(대량 처리=Haiku급, 보고서·챗=Sonnet급), **OpenAI(GPT)로 전환 가능**해야 한다.

### 6.4 안정성

- 수집 소스는 서로 독립적으로 실패 격리. yfinance·Google News 등 비공식 소스는 백오프·캐싱 필수, 실패 시 다음 실행에서 자동 보완.
- 파이프라인은 멱등: 같은 날짜 재실행 시 중복 데이터가 생기지 않는다.

### 6.5 언어

- 소스는 한/영/중, **사용자에게 보이는 모든 텍스트는 한국어**.

## 7. 아키텍처

```
[GitHub Actions (매일 06:00 KST, Python)]
  수집(네이버·GNews 링크 발견 / CnEVPost·DART·EDGAR 본문 / yfinance 주가)
  → 1차 게이트(스니펫: 관련성·대략 매핑)
  → 2차 정독(통과분 본문 페처로 취득 → LLM 분류·요약·테마태깅·관계추출, 본문 폐기)
  → Supabase Postgres 저장(집계 갱신 포함) → 데일리 브리프 + 트렌드 대시보드 데이터 생성 → Resend 이메일

[1회성 트렌드 시드 잡 (런칭 시 단독 실행)]
  네이버 과거 검색 + 리서치 에이전트 웹 조사
  → 최근 18개월 theme_period_stats·keyword_period_stats 채움 (data_origin=seeded)

[Supabase]
  Postgres(전 데이터) + Auth(이메일 OTP) + Storage(업로드 파일, 보고서 PDF)

[Next.js on Vercel (TypeScript)]
  대시보드·비교·보고서 보관함·챗(API Route에서 LLM tool-use)·관리자 화면
  마스터키 → 게스트 세션 발급
```

### 7.1 개념 데이터 모델

- `companies` — 회사 마스터 (companies.yaml과 동기화)
- `articles` — 기사·공시 메타 (제목, 링크, 발행일, 언론사, 자체 요약, 언어, 소스 종류, 중복 클러스터 id, `body_fetched` 본문 정독 성공 여부). **본문 원문 컬럼은 두지 않는다**(§6.2)
- `article_companies` — 기사↔회사 다대다 + 카테고리 태그
- `market_events` — 시장/정책 트랙 항목
- `themes` — 거시 테마 마스터 (이름, 설명, 상태: 후보/승인/기각)
- `article_themes` — 기사·시장이벤트 ↔ 테마 다대다
- `theme_period_stats` — 테마 × 주간 언급량 집계 (`data_origin`: seeded/measured)
- `keyword_period_stats` — 키워드 × 주간 언급량·증감률 집계 (`data_origin`: seeded/measured)
- `price_daily` — 일별 주가·시총
- `financials_quarterly` — 분기 재무 5종
- `manual_metrics` — 판매량·출하량·캐파 (업로드 반입분, 단위·기준 명시)
- `relations` — 관계 (회사쌍, 종류, 근거 링크들, 상태: 후보/승인/기각)
- `reports` — 생성된 보고서 메타 + 파일
- `pipeline_runs` — 실행 로그 (소스별 성공/실패/건수)
- `users`, `master_keys`, `email_subscriptions`

## 8. 단계별 릴리스

## 부록 B. 이벤트 분류 체계

회사 연결 카테고리 8종 + 기타:

| 코드 | 카테고리 | 예시 |
|---|---|---|
| `order` | 수주/공급계약 | 셀-OEM 공급계약, 소재 공급계약 |
| `capacity` | 증설/투자 | 신공장, 캐파 증설, 합작공장 착공 |
| `tech` | 기술/R&D | 신제품, 특허, 전고체 등 차세대 |
| `alliance` | 제휴/JV/M&A | 지분투자, 합작, 인수 |
| `earnings` | 실적/재무 | 분기실적, 유상증자, 신용등급 |
| `people` | 인사/조직 | CEO 교체, 조직개편 |
| `policy` | 정책/규제 | IRA, EU 배터리법, 중국 보조금 |
| `market` | 시장동향 | 원료가 동향, 수급 전망 |
| `etc` | 기타 | 위 어디에도 애매한 것 |

`policy`·`market`은 특정 회사에 속하지 않으면 **시장/정책 트랙**(`market_events`)으로, 특정 회사 관련이면 그 회사에도 연결한다.

## 부록 C. 분기 재무 지표

매출액 · 영업이익 · 영업이익률 · CAPEX · 재고자산 (연결 기준, 분기). 출처: DART XBRL(한국) / EDGAR companyfacts(미국). 그 외 상장지(유럽·일본·중국)는 Phase 1에서는 주가만, 재무는 2단계 검토.
