# plan.md — BatteryLens 구현 순서

> 각 Phase는 앞 Phase의 산출물에 의존한다. 순서대로 진행하고, 항목별 **완료 기준**을 충족해야 체크한다. 규칙은 [AGENTS.md](AGENTS.md), 요구사항 상세는 [PRD.md](PRD.md).

## Phase 0 — 기반 셋업

- [ ] **0.1 저장소 스캐폴드**: AGENTS.md의 구조대로 `pipeline/`(Python, pyproject) · `web/`(Next.js) · `supabase/` 생성.
  완료 기준: `pipeline/` 스모크 스크립트와 `web/` dev 서버가 로컬에서 뜬다.
- [ ] **0.2 외부 계정·키 준비 안내**: 필요한 키 목록(Supabase, Vercel, 네이버 API, DART API, Anthropic/OpenAI, Resend)과 발급 절차를 `docs/setup.md`로 작성. 발주자가 사람만 할 수 있는 단계(계정 가입 등)를 수행.
  완료 기준: 모든 키가 GitHub Actions secrets와 로컬 `.env`에 세팅되어 파이프라인 스모크가 통과.
- [ ] **0.3 약관 확인**: 네이버 뉴스 API 이용약관의 저장·상업적 이용 조항 원문 확인, 결과를 `docs/setup.md`에 기록 (PRD §9 리스크).
  완료 기준: 확인 결과와 대응 방침 1문단이 기록됨.
- [ ] **0.4 DB 스키마 v1**: PRD §7.1의 테이블을 `supabase/` 마이그레이션으로 생성.
  완료 기준: 마이그레이션이 빈 프로젝트에 오류 없이 적용된다.
- [ ] **0.5 companies.yaml 확정**: PRD 부록 A 초안의 티커를 yfinance 실측으로 검증하고, DART corp_code·SEC CIK 매핑 스크립트를 작성·실행해 채운다. 검증 결과를 발주자에게 보고해 목록 확정.
  완료 기준: 상장사 전체의 티커·corp_code·CIK가 실측 검증됨, 발주자 확정 완료.
- [ ] **0.6 LLM 중립 레이어**: `pipeline/llm/` — 프로바이더·모델 환경변수 전환, Claude/OpenAI 양쪽 스모크 통과.
  완료 기준: 같은 분류 호출이 두 프로바이더에서 모두 동작.

## Phase 1 — 수집·분류·축적 + 데일리 브리프 (PRD F1~F4)

- [ ] **1.1 수집기 6종**: naver / gnews(ko·en·zh) / cnevpost / dart / edgar / yfinance. 소스별 1모듈, 백오프·실패 격리, `pipeline_runs` 기록.
  완료 기준: 회사 3개 샘플로 6개 소스 전부 실데이터 수집 스모크 통과. 임의 1개 소스를 강제 실패시켜도 나머지가 완주.
- [ ] **1.2 분류·정제 단계**: 관련성 필터 → 회사 매핑(다대다) → 카테고리 태깅(부록 B) → 한국어 요약(영/중 번역 겸) → 이벤트 판정 → 중복 클러스터링. 프롬프트는 분리 파일.
  완료 기준: 실수집 기사 50건 샘플에 대한 결과를 발주자가 검수해 승인. 스냅샷 테스트 존재.
- [ ] **1.3 일일 워크플로**: `.github/workflows/daily.yml` — 매일 06:00 KST, workflow_dispatch 지원, 멱등(같은 날 재실행 시 중복 0).
  완료 기준: 실제 스케줄로 3일 연속 무인 성공, 같은 날 2회 실행 후 중복 행 0건.
- [ ] **1.4 백필**: 주가·분기 재무·공시 이벤트 과거 3년, 전체 회사.
  완료 기준: 전 상장사에 3년치 `price_daily`·`financials_quarterly`·공시 이벤트가 존재하고 표본 대조(회사 3개 × 지표 2개를 공시 원문과 비교) 일치.
- [ ] **1.5 데일리 브리프**: 파이프라인 말미에 한국어 브리프 생성 → DB 저장 + Resend 이메일 발송(구독자 목록).
  완료 기준: 실제 아침 브리프가 이메일로 도착, 모든 항목에 출처 링크, 본문 전문 미포함.
- [ ] **1.6 최소 웹 + 인증**: 로그인(이메일 OTP, 허용 도메인 제한) + 마스터키 입력 → 오늘·과거 브리프 열람 화면.
  완료 기준: 허용 도메인 이메일로 가입 성공, 비허용 도메인 거부, 마스터키로 게스트 접속 성공.
- [ ] **1.7 품질 튜닝 기간(2주)**: 운영하며 발주자 피드백으로 필터·분류 프롬프트 개선.
  완료 기준: 발주자가 "브리프를 매일 실무에 쓸 수 있다"고 확인.

## Phase 2 — 대시보드 (PRD F5, F9 일부)

- [ ] **2.1 회사 페이지**: 프로필 + 수치 시계열 차트(기간 선택) + 이벤트 타임라인(카테고리 필터) + 주가 차트 이벤트 마커 오버레이.
  완료 기준: 임의 회사에서 3년 주가 위에 이벤트 마커가 찍히고 클릭 시 출처로 이동.
- [ ] **2.2 비교 화면**: 회사 2~5개 선택, 지표 겹쳐 그리기(주가 % 정규화 옵션), 타임라인 나란히.
  완료 기준: 국적이 다른 회사 3개(예: 한·중·미)를 한 차트에서 비교 가능.
- [ ] **2.3 시장/정책 트랙 페이지**.
  완료 기준: `policy`·`market` 항목이 회사 페이지가 아닌 이 페이지에 시간순 표시.
- [ ] **2.4 관리자 — 수동 지표 업로드**: 판매량·출하량·캐파 xlsx/csv 업로드, 스키마 검증·오류 리포트, 회사 페이지 차트 반영.
  완료 기준: 정상 파일 반입 성공, 오류 파일은 행 단위 사유와 함께 거부.
- [ ] **2.5 관리자 — 재분류·회사 관리**: 잘못 분류된 기사 카테고리 수정, 회사 추가/비활성.
  완료 기준: 수정이 즉시 화면에 반영.

## Phase 3 — 정기 보고서 (PRD F6)

- [ ] **3.1 위클리**: 매주 월 자동 생성(HTML→PDF) + 보관함 + 재생성 버튼.
  완료 기준: 2주 연속 자동 생성 성공, PDF 다운로드 정상, 인용 전부 요약+출처 링크.
- [ ] **3.2 먼슬리**: 위클리와 동일 구조, 월 1일 자동.
  완료 기준: 1회 자동 생성 성공(발주자 내용 검수 포함).
- [ ] **3.3 반기 초안**: 온디맨드 버튼 → 마크다운 + 차트 이미지 zip.
  완료 기준: 생성물을 발주자가 문서 도구로 열어 편집 가능.

## Phase 4 — 챗 + 관계도 (PRD F7~F8)

- [ ] **4.1 챗 (DB 근거)**: tool-use로 DB 조회(회사·기간·카테고리·시계열·비교), 근거 링크 필수 표시, 근거 없으면 없다고 답변.
  완료 기준: "A사와 B사 최근 1년 증설 발표 비교" 류 질문에 DB 근거 링크와 함께 정답. DB에 없는 사안 질문엔 부재를 명시.
- [ ] **4.2 챗 웹검색 확장**: 사용자 명시 요청 시에만 웹검색, 결과는 DB 근거와 구분 표시.
  완료 기준: 요청 없는 대화에서 웹검색 미발동, 요청 시 발동·구분 표시 확인.
- [ ] **4.3 관계 추출·승인**: 분류 단계에 관계 후보 추출 추가 → 관리자 승인 대기열 → 승인분만 반영.
  완료 기준: 실기사에서 추출된 후보를 승인/기각하는 흐름이 동작, 미승인 후보는 관계도에 비노출.
- [ ] **4.4 관계도 화면**: 회사 중심 그래프, 엣지 클릭 시 근거 목록.
  완료 기준: 승인된 관계만 표시되고 근거 링크로 이동 가능.

## Phase 경계 밖 (하지 않는 것)

PPT 자동 생성 · 중국 전문매체 크롤링 · 유료 데이터 자동 수집 · 상시 웹검색 챗 — PRD §3.2가 단일 출처.
