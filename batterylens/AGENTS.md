# AGENTS.md — BatteryLens 작업 규칙

배터리 밸류체인 시장 인텔리전스 서비스. **무엇을** 만드는지는 [PRD.md](PRD.md), **어떤 순서로** 만드는지는 [plan.md](plan.md)가 단일 출처다. 이 문서는 **어떻게 일할지**만 다룬다.

## 작업 순서

1. 작업 시작 전 plan.md에서 현재 Phase와 담당 작업 항목을 확인한다. Phase를 건너뛰거나 뒤 Phase의 기능을 미리 만들지 않는다.
2. 작업 항목의 **완료 기준**(plan.md에 항목별로 명시)을 충족했는지 스스로 검증한 뒤 완료로 표시한다. 검증 없는 완료 표시는 미완료다.
3. 설계가 PRD와 충돌하면 구현을 멈추고 발주자에게 질문한다. PRD를 임의로 재해석하지 않는다.
4. plan.md의 체크박스를 진행에 맞춰 갱신하고 커밋에 포함한다.

## 불변 규칙 (모든 Phase 공통)

- **저작권**: 기사 본문 전문은 저장하지 않는다. 저장은 제목 + 출처 링크 + 발행일 + 언론사명 + 자체 LLM 요약만 (PRD §6.2).
- **LLM 중립**: 모든 LLM 호출은 `llm/` 추상화 레이어를 거친다. 프로바이더(기본 Claude, 전환 OpenAI)·모델명은 환경변수로만 지정하고, 호출부 코드에 모델명을 하드코딩하지 않는다 (PRD §6.3).
- **시크릿**: API 키·마스터키는 환경변수와 GitHub Actions secrets로만 다룬다. 코드·설정 파일·로그·커밋에는 키 이름만 등장한다.
- **멱등**: 파이프라인은 같은 날짜로 재실행해도 중복 행이 생기지 않는다 (자연키 upsert).
- **무료 티어**: 유료 플랜 전환·과금이 발생하는 설정 변경은 발주자 승인 없이 하지 않는다.
- **한국어**: 사용자에게 보이는 모든 텍스트(UI·브리프·보고서·챗 답변·이메일)는 한국어다. 코드 식별자·커밋 메시지는 영어다.

## 저장소 구조

```
pipeline/      # Python — 수집·분류·요약·브리프·보고서 생성 배치
  sources/     # 소스별 수집기 1파일 1소스 (naver, gnews, cnevpost, dart, edgar, yfinance)
  llm/         # LLM 프로바이더 중립 레이어 + 프롬프트 (프롬프트는 코드와 분리된 파일)
web/           # Next.js(TypeScript) — 대시보드·챗·관리자
supabase/      # 마이그레이션 SQL (스키마의 단일 출처)
companies.yaml # 회사 마스터 (PRD 부록 A에서 확정)
.github/workflows/  # daily.yml (수집), weekly.yml·monthly.yml (보고서)
```

- 수집기는 **1소스 1모듈**: 한 소스의 장애·교체가 다른 소스에 닿지 않게 한다.
- DB 스키마 변경은 `supabase/` 마이그레이션 파일로만 한다.

## 코딩 규칙

- **파이프라인 = Python, 웹 = TypeScript.** 영역을 넘는 언어 혼용은 하지 않는다.
- 실행·테스트·린트 명령은 `pipeline/pyproject.toml`과 `web/package.json`의 scripts가 단일 출처다. 새 명령을 만들면 거기에 등록한다.
- 외부 데이터(티커, corp_code, CIK, RSS URL, API 응답 필드)는 **실측으로 검증**한 뒤 사용한다. PRD 부록 A의 티커는 초안이며 검증 대상이다.
- 비공식 소스(yfinance, Google News RSS) 호출부에는 지수 백오프와 캐싱을 붙이고, 실패는 `pipeline_runs`에 기록한 뒤 다음 소스로 진행한다.
- 프롬프트는 코드와 분리된 파일로 두고 버전 관리한다 — 분류 품질 개선이 코드 수정 없이 가능해야 한다.

## 검증

- 파이프라인 변경 시: 소량 샘플(회사 2~3개)로 **실제 API를 호출하는 스모크 테스트**를 통과시킨 뒤 완료로 본다. 분류·요약 등 LLM 단계는 고정 입력 스냅샷 테스트로 회귀를 막는다.
- 웹 변경 시: `web/` 의 lint·typecheck·build를 통과시킨다.
- 시크릿이 필요한 테스트는 환경변수 부재 시 skip 처리해 CI를 깨뜨리지 않는다.
